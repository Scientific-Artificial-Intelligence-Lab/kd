# kd2: 符号回归通用实验平台

> 架构总结 | 2026-01

---

## 一、项目定位

kd2 是一个**符号回归领域（尤其是 PDE 发现）的通用实验平台**。

**核心价值**：将 DISCOVER、SGA、DLGA、PySR 等不同算法统一到一个平台上，实现算法可插拔、评估可复现、结果可对比。

**解决的问题**：
- 当前各算法实现分散，数据格式不统一，难以公平对比
- 重复造轮子：每个算法都要自己实现数据处理、评估、可视化
- 实验难复现：配置管理混乱，结果难以追踪

---

## 二、核心设计思想

### 2.1 算法与平台分离

传统做法是每个算法自己实现完整流程，kd2 的思路是**把算法和平台解耦**：

```
┌─────────────────────────────────────────┐
│           算法插件（可插拔）              │
│   DISCOVER │ SGA │ DLGA │ PySR │ ...    │
│                                         │
│   只负责：提出候选表达式 + 接收反馈更新   │
└────────────────────┬────────────────────┘
                     │ propose() / update()
                     ▼
┌─────────────────────────────────────────┐
│              平台核心                    │
│                                         │
│   统一负责：执行、评估、缓存、日志        │
└─────────────────────────────────────────┘
```

**插件接口设计**：

```python
class AlgorithmPlugin:
    def propose(k) -> List[表达式]    # 生成 k 个候选
    def update(feedback) -> None       # 根据评估结果更新内部状态
```

**工作流程**：
1. 插件提出候选表达式
2. 平台统一执行和评估（带缓存，避免重复计算）
3. 平台把评估结果反馈给插件
4. 插件更新策略，继续搜索

**好处**：
- 算法开发者专注算法逻辑，不用重复写数据处理、评估、缓存
- 不同算法在同一平台上公平对比
- 便于未来接入新算法

### 2.2 可微计算图：核心技术基础

**核心洞察**：无论是符号树还是 token 序列，本质都是一个**计算顺序**。只要我们用 PyTorch 构建计算图，就可以：
- 对任意表达式执行数值计算
- 通过自动微分对任意子表达式求导
- 将观测数据带入计算图，计算残差，评估准确度

```
        符号表达式                    PyTorch 计算图
            │                              │
            ▼                              ▼
    u_t = u · u_x + u_xx    ───→    output = u * u_x + u_xx
                                           │
                                    torch.autograd.grad
                                           │
                                           ▼
                                    可对任意节点求导
```

**为什么用 PyTorch Tensor 全程**：
1. **自动微分**：利用 PyTorch 的 autograd，可以对计算图中任意节点求导
2. **端到端可微**：未来可支持 PINN 等需要反向传播优化的场景
3. **GPU 加速**：大规模数据和批量评估可利用 GPU

**两条导数计算路径**：

| 路径 | 方法 | 速度 | 精度 | 适用场景 |
|------|------|------|------|---------|
| 有限差分 | 数值近似 | 快 | 近似 | 预计算导数（u_x, u_xx） |
| 自动微分 | torch.autograd | 慢 | 精确 | 复合表达式求导 |

**Open-form Diff**：对任意复合表达式求导的能力

```python
# 预计算导数（查表，快）
u_x = derivative_provider.get_derivative("u", "x", 1)

# Open-form diff（自动微分，慢但强大）
# 可以对任意复合表达式求导，如 diff(u·u_x, x)
result = torch.autograd.grad(expression, coords["x"], ...)
```

这是 DISCOVER 等算法的关键能力：能够搜索包含复合微分的表达式。

### 2.3 统一中间表示（IR）

不同算法内部表示方式不同：
- SGA 用树结构
- DISCOVER 用 token 序列
- PySR 用 SymPy 表达式

kd2 定义了**统一的中间表示（IR）**，作为算法和平台之间的桥梁：

```
                数学表达式
                    │
                    ▼
        u_t = -u · u_x + 0.1 · u_xx
                    │
    ════════════════════════════════════════════════════
                    │
                    ▼
    ┌───────────────────────────────┐
    │  第一层：GenIR (前缀 token 序列) │  ← 唯一真相：存储/缓存/去重/对比
    │  "add,mul,neg,u,ux,mul,0.1,uxx" │
    └───────────────┬───────────────┘
                    │ 转换
                    ▼
    ┌───────────────────────────────┐
    │  第二层：AnalysisIR (AST 树)    │  ← 视图：结构分析/约束检查/可视化
    │         add                    │
    │        /   \                   │
    │      mul    mul                │
    │     / \    /  \                │
    │   neg  u  0.1  uxx             │
    │    |                           │
    │    ux                          │
    └───────────────┬───────────────┘
                    │ 转换（Phase 5）
                    ▼
    ┌───────────────────────────────┐
    │  第三层：ExecIR (DAG + CSE)     │  ← 优化：公共子表达式消除/执行优化
    │  [计划中，难度较高]              │
    └───────────────────────────────┘
```

**三层 IR 的职责**：

| IR 层 | 表示形式 | 职责 | 状态 |
|-------|---------|------|------|
| **GenIR** | 前缀 token 序列 | 存储、缓存键、日志、去重 | ✅ 核心 |
| **AnalysisIR** | AST 树 | 结构分析、约束检查、执行、可视化 | ✅ 核心 |
| **ExecIR** | DAG 图 | 公共子表达式消除、执行优化 | 📋 Phase 5 |

**设计原则**：
- GenIR 是「唯一真相」，AnalysisIR 是「视图」，两者可互相转换
- ExecIR 只用于执行优化，不用于生成（生成仍用 Tree/prefix，否则会破坏 DISCOVER 等算法的结构感知）

**ExecIR 的意义与难度**（Phase 5 规划）：

当表达式变复杂时，会出现大量重复计算：
```
表达式: sin(u) + cos(sin(u)) + exp(sin(u))
        ~~~~~~       ~~~~~~       ~~~~~~
        重复计算了 3 次 sin(u)
```

ExecIR 通过 DAG（有向无环图）+ CSE（公共子表达式消除）优化：
```
原始：3 次 sin(u) 计算
优化：1 次 sin(u) 计算，结果复用
```

**难度说明**：
- 需要设计 DAG 数据结构和转换算法
- 需要处理哈希冲突、交换律等等价性问题
- 需要与缓存系统配合
- 目前优先级较低，Phase 5 再实现

## 三、五层架构

```
┌─────────────────────────────────────────────────────────────┐
│                    应用层 (Application)                      │
│         CLI  │  Web UI  │  Agent API  │  Notebooks          │
├─────────────────────────────────────────────────────────────┤
│                    实验层 (Experiment)                       │
│    实验管理  │  结果存档  │  可视化  │  配置管理  │  日志    │
├─────────────────────────────────────────────────────────────┤
│                    插件层 (Plugin)                           │
│        DISCOVER  │  SGA  │  DLGA  │  PySR  │  自定义        │
├─────────────────────────────────────────────────────────────┤
│                    核心层 (Core)                             │
│    IR 系统  │  执行器  │  评估器  │  约束系统  │  缓存      │
├─────────────────────────────────────────────────────────────┤
│                    基础层 (Foundation)                       │
│     数据加载  │  导数计算（FD/Autograd）│  PyTorch          │
└─────────────────────────────────────────────────────────────┘
```

### 3.1 各层职责

**基础层 (Foundation)**
- 数据加载：支持多种格式（.mat, .npy, .npz），统一为 PDEDataset
- 导数计算：
  - FiniteDiffProvider：有限差分，快速预计算 u_x, u_xx 等
  - AutogradProvider：自动微分，支持 open-form diff
- 技术栈：PyTorch 2.x（计算图 + 自动微分）

**核心层 (Core)**
- IR 系统：GenIR ↔ AnalysisIR 转换，未来扩展 ExecIR
- 执行器：将 IR 在数据上执行，构建 PyTorch 计算图，得到数值结果
- 评估器：计算准确度（MSE, R²）和复杂度（树深度、节点数）
- 约束系统：过滤非法表达式（嵌套过深、数值溢出、别名重复）
- 缓存：表达式级缓存（DiskCache），同一表达式只计算一次

**插件层 (Plugin)**
- 各算法作为插件实现 propose/update 接口
- 插件只关心搜索策略，不关心执行和评估细节
- 支持自定义插件扩展

**实验层 (Experiment)**
- 实验管理器：调度 propose → evaluate → update 循环
- 结果存档：收集最优表达式，提取 Pareto 前沿
- 配置管理：Hydra 管理实验配置
- 日志追踪：WandB 记录实验过程

**应用层 (Application)**
- CLI 工具：命令行运行实验
- Web UI：未来支持在线配置和可视化
- Agent API：未来支持自动实验调度

### 3.2 数据流

```
数据集 (u, x, t)
        │
        ▼
┌─────────────────────────────┐
│  导数计算                    │
│  FiniteDiff: u_x, u_xx, ... │  预计算，存入 ExecutionContext
│  Autograd: diff(expr, x)    │  按需计算
└─────────────────────────────┘
        │
        ▼
┌─────────────────────────────┐
│  执行上下文 (ExecutionContext)│  包含：场变量、坐标、预计算导数
└─────────────────────────────┘
        │
        ▼
算法插件 ──propose──→ 候选表达式 (GenIR)
    ▲                        │
    │                        ▼
    │                转换为 AnalysisIR
    │                        │
    │                        ▼
    │                ┌───────────────────┐
    │                │ 执行器：构建计算图  │
    │                │ 在数据上执行       │
    │                │ 支持自动微分       │
    │                └───────────────────┘
    │                        │
    │                        ▼
    │                评估器：MSE, 复杂度, AIC
    │                        │
    │                        ▼
    └───update─────── 评估结果 (Feedback)
```

## 四、关键技术决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 数据类型 | PyTorch Tensor | 支持自动微分，构建可微计算图 |
| IR 设计 | 两层（GenIR + AnalysisIR） | 兼顾存储效率和分析便利；ExecIR 延后 |
| 插件接口 | propose/update | 平台统一控制评估，便于缓存和并行 |
| 首个验证插件 | SGA | 代码简单清晰，适合验证架构 |
| 导数计算 | 有限差分 + 自动微分 | FD 快速用于预计算；Autograd 支持 open-form diff |
| 计算图保留 | 默认关闭，可选开启 | 性能优先；PINN 等场景可开启 |
| 评估模式 | 线性回归优先 | STRidge/Lasso 求解系数，稳定高效 |
| 缓存方案 | 本地磁盘缓存 | 单机科研友好，无需运维 |
| 哈希策略 | SHA256 + 交换律归一化 | a+b 与 b+a 共享缓存 |
| 配置管理 | Hydra | 科研标配，配置管理优雅 |
| 实验追踪 | WandB | 科研标配，支持可视化和对比 |

## 七、总结

kd2 的核心思想是 **"算法插件化 + 平台标准化 + 计算图可微"**：

- **可微计算图**：用 PyTorch 构建计算图，支持自动微分，可对任意表达式求导
- **统一表示**：用 IR 统一不同算法的输出格式（GenIR → AnalysisIR → ExecIR）
- **算法插件化**：不同符号回归算法作为插件接入，只负责搜索策略
- **平台标准化**：平台提供统一的数据处理、执行、评估、缓存、日志
- **结果可比**：不同算法在同一平台上公平对比，实验可复现
