    Batch experiments

    kd.harness runs a matrix of fits and keeps what it ran. The loop is four calls: an ExperimentPlan of PlanEntry rows states the matrix, run_plan executes it into a fresh directory, EvidenceStore.load reopens that directory and re-verifies it, and build_consensus groups the runs by the law each one selected. merge_stores combines the stores of separate run_plan batches into one store before that last step. The store's guarantees and the meaning of the consensus axes are described under Batch experiments and evidence.

    These names are imported from the subpackage rather than the package root: from kd.harness import ExperimentPlan, run_plan. Listed below are the entry points a caller writes; the module also carries the artifact machinery that run_plan and build_consensus drive on their own.

    run_episode runs one plan entry and returns its EpisodeOutcome; given run_dir=, it also creates and seals that entry's run directory.

    environment_fingerprint returns the runtime fingerprint stored in a new evidence index: the KD, CPython and PyTorch versions, the platform, the git commit and the working-tree status. With strict=True it raises instead of recording a field it cannot read as "unknown".

    ProcessSupervisor, run_supervised, ProcessResult and ProcessEnding supervise a single worker command and every process it starts, for a caller that launches its own worker processes. On Linux the command leads its own process group, and a time limit or a stop request sends SIGTERM to the group, then SIGKILL after a grace period. On Windows, which has no signal that asks a process tree to stop, the command runs in a Job Object that is terminated when the grace period ends. Process supervision does not support other platforms yet. The optional memory cap (memory_max_gb) is a systemd user scope on Linux, the command prefix that build_capped_command assembles, and a limit on the committed memory of the Job Object on Windows. check_memory_cap_available checks that the platform's cap can be applied before any work starts.

    run_plan 

    run_plan(
    plan: ExperimentPlan,
    *,
    datasets: Mapping[str, PDEDataset | TabularDataset],
    store_root: Path,
    model_factory: Callable[..., Any] = Model,
    device: str | None = None,
    recording: RecordingOptions | None = None,
    catalog_path: Path | None = None,
    parallel: ParallelOptions | None = None,
) -> PlanRunResult

    Pre-flight, then run every plan entry into a fresh store.

    Parameters:

    • plan (ExperimentPlan) –

      The ordered execution matrix to run.

    • datasets (Mapping[str, PDEDataset | TabularDataset]) –

      Maps each dataset_ref to a loaded PDEDataset or a public TabularDataset (normalized once at entry through the same seam as Model.fit).

    • store_root (Path) –

      Fresh directory for the EvidenceStore (must not exist or must be empty; append/resume is out of scope).

    • model_factory (Callable[..., Any], default: Model ) –

      Facade constructor forwarded to run_episode; injectable so unit tests can stub the fit (serial runs only).

    • device (str | None, default: None ) –

      Execution-environment parameter forwarded to run_episode and, from there, conditionally to the facade. None leaves the serial-execution call form literally unchanged.

    • recording (RecordingOptions | None, default: None ) –

      When set, each entry runs inside a standard run dir <store_root>/runs/entry-NNNN/ (numbered by plan entry, matching records/entry-NNNN.json) wired per the options.

    • catalog_path (Path | None, default: None ) –

      Cross-run ledger to append one kd-runcat-v1 row per outcome (requires recording; rows carry the entry index, the store's plan hash and paths relative to the catalog file).

    • parallel (ParallelOptions | None, default: None ) –

      Run entries in supervised child processes; None runs them serially in this process.

    Returns:

    • PlanRunResult –

      A PlanRunResult with the store root and one outcome per entry.

    Raises:

    • ValueError –

      If pre-flight finds any unknown instrument or unresolved dataset_ref (all violations are collected into the message), if catalog_path is given without recording, or, with parallel, if model_factory is not Model, an instrument was registered in this process only (a child process would not have it), an entry device is not None/"cpu"/"cuda", or the card pool cannot serve parallel.limits.

    persist_outcome: Callable[[EpisodeOutcome], None]
    | None = None,
    extra_callbacks: Sequence[RunnerCallback] | None = None,
) -> EpisodeOutcome

    Run one plan entry and return a totalized EpisodeOutcome.

    Parameters:

    • entry (PlanEntry) –

      The declarative plan entry to execute.

    • entry_index (int) –

      The entry's position in the plan (for logging / storage).

    • dataset (PDEDataset | TabularDataset) –

      The loaded dataset resolved from entry.dataset_ref.

    • model_factory (Callable[..., Any], default: Model ) –

      Facade constructor; injectable so unit tests can stub it.

    • device (str | None, default: None ) –

      Execution-environment knob forwarded to the facade (a sibling of verbose).

    • run_dir (Path | None, default: None ) –

      A FRESH standard run directory (kd.search.run_dir) this episode claims and seals: iteration events, phase lines, a manifest-managed checkpoints/ and the run-level manifest all land there. None disables run-directory recording.

    • run_id (str | None, default: None ) –

      The operational handle of this episode's run dir, for a caller that names the run before it starts (a queue that files its own state under the same id). Requires run_dir and must be non-empty.

    • resume_from (Path | str | None, default: None ) –

      Optional checkpoint path forwarded to model.fit — harness-owned, so retry lanes can resume a prior segment's checkpoint; lineage lands in the record's manifest (M4).

    • reseed (bool, default: False ) –

      Forwarded to model.fit to turn that resume into a BRANCH (K4): the restored search state is kept and the random streams are re-derived from entry.seed. True without resume_from is the facade's ValueError, totalized as a "raised" outcome like any other fit failure.

    • sketch (Sketch | SketchSpec | None, default: None ) –

      Forwarded to model.fit(sketch=...) as given; a shorthand kd.SketchSpec is resolved there, against dataset.

    • verify (VerifyPolicy | None, default: None ) –

      Forwarded to model.fit(verify=...). None lets the facade resolve the sketch exit's own default (kd.SKETCH_EXIT_VERIFY); it is NOT the report-only VerifyPolicy(), which a caller opts into explicitly.

    • max_seconds (float | None, default: None ) –

      Forwarded to model.fit(max_seconds=...): the fit's wall-clock budget, whose clock starts when the facade's fit is called. Like the sketch, it stays out of the plan's identity hash.

    • recording (RecordingOptions | None, default: None ) –

      Knobs for the run-dir surfaces; defaults to RecordingOptions() when run_dir is set.

    • record_ref (str | None, default: None ) –

      Pointer (relative to run_dir) to the sealed record's external home (the store's records/entry-NNNN.json) — the run dir then references instead of duplicating it. Requires run_dir.

    • persist_outcome (Callable[[EpisodeOutcome], None] | None, default: None ) –

      Called with the finished outcome BEFORE the run dir is sealed, so the record record_ref points at is written before the manifest that advertises it.

    • extra_callbacks (Sequence[RunnerCallback] | None, default: None ) –

      Additional RunnerCallback instances forwarded to the facade's callbacks seam. On the recording path they follow the harness-owned IterationEventEmitter.

    Returns:

    • EpisodeOutcome –

      An EpisodeOutcome whose status is one of "completed", "raised", or "no_record"; when run_dir is set it also carries the sealed run dir's run_id / run_dir.

    ProcessSupervisor

    Launch a command and supervise its whole process tree.

    Parameters:

    • command (Sequence[str]) –

      Executable and arguments, without shell expansion.

    • env (Mapping[str, str]) –

      Complete environment for the command.

    • hard_seconds (float | None) –

      Elapsed limit from launch, or None for no time limit.

    • grace_seconds (float) –

      Wait after the first escalation step and again after the second, in seconds.

    • cwd (Path | None, default: None ) –

      Working directory, or None to inherit the current directory.

    • stdout (IO[Any] | None, default: None ) –

    ProcessResult dataclass

    Observed leader termination, group cleanup, timing and sampled memory.

    Attributes:

    • pid (int) –

      Leader PID; on Linux also the supervised process group ID.

    • returncode (int | None) –

      Leader exit status, or None if still alive at the bound. On Linux a negative value is the signal that ended it. On Windows it is the unsigned 32-bit exit code, and a leader ended by the Job termination reports 1.

    • ended_by (ProcessEnding) –

      Last escalation stage reached while the leader was alive.

    • stop_reason (Literal['timeout', 'requested'] | None) –

      timeout or requested when either initiated the escalation; None for natural exit and its descendant cleanup.

    • sigkill_used (bool) –

      Whether the group SIGKILL step was taken, including descendant cleanup and an OS refusal of that signal. Always False on Windows.

    • started_at (str) –

      Launch time as a UTC ISO 8601 string.

    • term_sent_at (str | None) –

      UTC time of the SIGTERM step, or None. Always None on Windows.

    • kill_sent_at (str | None) –

      UTC time of the SIGKILL step, or None. Always None on Windows.

    • ended_at (str) –

      UTC time when supervision finished.

    • wallclock_seconds (float) –

      Elapsed monotonic seconds from launch to completion.

    • peak_rss_bytes (int) –

      Maximum sampled sum of group members' resident memory.

    • left_descendants (bool) –

      Whether the leader exited before escalation and left members requiring cleanup.

    • group_emptied (bool) –

      Whether the group was confirmed empty. False means the grace after the SIGKILL or Job termination step expired with members still present.

    • memory_backend (Literal['linux-cgroup', 'windows-job'] | None) –

      Kernel mechanism enforcing the memory cap: linux-cgroup limits resident memory, windows-job limits committed memory. None when no cap was requested.

    • memory_limit_bytes (int | None) –

      The enforced cap in bytes, or None without a cap.

    • peak_committed_bytes (int | None) –

      Windows: the Job's peak committed memory as the kernel reports it, with or without a cap. The kernel counts a request the cap refused, so the value can exceed the cap. None on Linux.

    • job_terminated_at (str | None) –

      UTC time of the Job termination step (Windows), including descendant cleanup, or None.
